# ایتو — کلاینت تلگرام با ۲۰۰۶ قابلیت

> تلگرام رسمی خوب است. ایتو همان است، ولی با یک جعبه‌ابزارِ گنده که تلگرام حاضر نشده بدهد.

یک کلاینت اندرویدی روی **TDLib رسمی** (لاگین واقعی با شماره)، نوشته‌شده با Kotlin و Jetpack Compose،
با کاتالوگی از **۲۰۰۶ قابلیت** که داخل تنظیمات دسته‌بندی و جست‌وجو می‌شود — به‌علاوه‌ی یک بخش **+۱۸**
که با **تشخیص سن از روی چهره، کاملاً آفلاین** باز می‌شود.

---

## اول از همه: شمارش صادقانه

سفارش این بود که «قابلیت‌ها الکی نباشند و مثلاً تغییر رنگ صورتی و آبی دو تا حساب نشوند». پس:

| نوع | تعداد | یعنی چه |
| --- | --- | --- |
| موتور اختصاصی | ۹۳۹ | کد جداگانه‌ای برای همان کار وجود دارد |
| محتوای واقعی | ۲۹۱ | متن/هنر/قالب واقعی که با فعال‌سازی وارد اپ می‌شود |
| ترکیب دو موتور | ۷۷۶ | «ابزار متن X» × «مسیر اجرای Y» — هر کدام رفتار متفاوت |
| **جمع** | **۲۰۰۶** | |

* هیچ آیتمی نسخه‌ی رنگی/زبانیِ آیتم دیگر نیست. یک **تست واحد** (`CatalogTest`) دقیقاً همین را چک می‌کند:
  عنوان تکراری، شناسه‌ی تکراری، و آیتم‌های پرکننده‌ی رنگی باعث **شکست بیلد** می‌شوند.
* همین جدول داخل خود اپ هم هست: تنظیمات ← **صفحه‌ی صداقت**.
* «ترکیبی» یعنی: آزمایشگاه متن ۱۹۴ ابزار واقعی دارد و هر کدام روی چهار مسیر می‌نشیند
  (پیام ارسالی، پیام دریافتی، ابزار سریع، کلیپ‌بورد). «مورس روی ارسالی» و «مورس روی دریافتی»
  دو رفتار متفاوت‌اند، نه دو اسم برای یک چیز.

---

## چیزهایی که تلگرام رسمی ندارد

* **آزمایشگاه متن دوطرفه** — ۱۹۴ ابزار واقعی: نیم‌فاصله‌ی خودکار، فینگلیش ↔ فارسی، مورس، مبنا،
  ماسک‌کردن شماره کارت و تلفن، حذف پارامترهای رهگیری لینک، تبدیل تاریخ شمسی/میلادی،
  حل عبارت ریاضی داخل متن، مبلغ به حروف، زالگو، و… . همه‌شان در اپ زنده قابل آزمایش‌اند.
* **ویراستار فارسی** با ۴۰ قاعده‌ی واقعی نگارشی.
* **موتور قانون‌نویسی محلی**: ۷۰ تریگر + ۶۰ اکشن، بدون ذره‌ای کد.
* **یادداشت، برچسب و لقب روی مخاطب و پیام** — چیزی که هیچ‌وقت به سرور نمی‌رود.
* **آمار محلی**: زمان پاسخ واقعی، شاخص شب‌بیداری، بدهی پاسخ، توزیع نوع فایل‌ها.
* **گیت سنی با چهره** + رجیسترهای زبانی رابط کاربری.

## زبانِ برنامه، سه‌حالته

کل رشته‌های رابط کاربری از یک جدول سه‌ستونه می‌آید:

| رجیستر | نمونه (لیست چت خالی) |
| --- | --- |
| مؤدب | «هنوز گفت‌وگویی وجود ندارد.» |
| خودمونی | «اینجا خالیه… یکی رو بزن به تور.» |
| بی‌پرده (+۱۸) | «اینجا از خالی هم خالی‌تره. یه پیام بده به کسی، نمیر که.» |

رجیستر سوم فقط بعد از پاس‌شدن گیت سنی فعال می‌شود.

## بخش +۱۸ و تشخیص سن

حالت **سخت‌گیر** (همان که انتخاب شد) یعنی:

1. مدل تخمین سن روی دستگاه اجرا می‌شود (TensorFlow Lite، `assets/age_model.tflite`، MIT).
2. حداقل ۶ نمونه از فریم‌های مختلف + میانه‌گیری.
3. حداقل ۲ تست **زنده‌بودن**: پلک زدن، چرخش سر، لبخند (جلوی «عکسِ عکس» را می‌گیرد).
4. بیش از یک چهره در کادر ⇐ رد. تخمین‌های پراکنده ⇐ رد. مدل بارگذاری نشود ⇐ رد.
5. میانه باید از `۱۸ + حاشیه‌ی اطمینان` بیشتر باشد؛ مرزِ دقیقاً ۱۸ هم رد می‌شود.
6. هیچ فریمی ذخیره یا ارسال نمی‌شود؛ نتیجه فقط روی همین گوشی می‌ماند.

> صادقانه: تخمین سن از چهره خطا دارد. این یک سدِ منطقی است، نه کارت شناسایی — و دقیقاً
> به همین دلیل، «نامطمئن» در حالت سخت‌گیر یعنی **قفل**.

این بخش هیچ محتوای بزرگسالی تولید یا میزبانی نمی‌کند؛ فقط دسترسی، فیلتر و لحن را مدیریت می‌کند.

## گرفتن APK

هر پوش روی این شاخه، ورک‌فلوی `.github/workflows/android.yml` را اجرا می‌کند:

* تست‌های واحد ← لینت ← `assembleDebug` و `assembleRelease`
* یک جاب جداگانه اپ را روی **شبیه‌ساز** نصب می‌کند، `monkey` می‌اندازد رویش و اگر
  `FATAL EXCEPTION` ببیند بیلد را قرمز می‌کند.
* خروجی‌ها در تبِ Actions زیر artifact ‏`ito-apks` هستند و نسخه‌ی نهایی در پوشه‌ی `dist/`.

### بیلد روی دستگاه خودتان

```bash
git clone <این مخزن> && cd Ito_TELEGRAM
python3 tools/gen_features.py          # ساخت کاتالوگ (اختیاری، خروجی داخل مخزن هست)
./gradlew :app:assembleDebug           # یا: gradle :app:assembleDebug
```

هنگام بیلد، بسته‌ی رسمی TDLib از `core.telegram.org/tdlib/tdlib.zip` دانلود می‌شود.
اگر شبکه نداشتید:

```bash
ITO_SKIP_TDLIB=1 gradle :app:assembleDebug   # بیلد می‌شود، فقط در حالت آفلاین بالا می‌آید
```

## راه‌اندازی بعد از نصب

۱. برو به `my.telegram.org` و `api_id` و `api_hash` بگیر.
۲. در اپ: **تنظیمات ← اتصال به تلگرام** ← واردشان کن ← «ذخیره و اتصال مجدد».
۳. **ورود با شماره** ← کد ← (در صورت وجود) رمز دومرحله‌ای.

بدون کلید یا بدون کتابخانه‌ی نیتیو، اپ **کرش نمی‌کند**: می‌رود روی حالت نمایشی با داده‌ی محلی
تا بشود همه‌ی ۲۰۰۶ قابلیت را واقعاً لمس کرد.

## معماری

```
app/src/main/java/ito/telegram/
├── core/            Prefs، کاتالوگ، رجیسترهای زبانی
│   └── text/        TextLab (۱۹۴ ابزار)، TextPipeline، JalaliDate
├── tg/              Gateway، TdLibGateway (بازتابی)، DemoGateway، TelegramRepo
├── adult/           AgeGate (منطق خالص و تست‌شده)، AgeEstimator (TFLite)
└── ui/screens/      چت‌ها، چت، کاتالوگ، آزمایشگاه، +۱۸، اسکن سن، تنظیمات، صداقت، دیباگ
tools/gen_features.py  مولد کاتالوگ ۲۰۰۶ آیتمی
```

**چرا TDLib بازتابی (reflection) صدا زده می‌شود؟** چون فایل‌های `org.drinkless.tdlib` هنگام بیلد
دانلود می‌شوند. این‌طوری اگر دانلود شکست بخورد اپ باز هم کامپایل و اجرا می‌شود، و تغییر نام
فیلدها بین نسخه‌های TDLib هم چیزی را نمی‌شکند.

## اشکال‌زدایی

* داخل اپ: **تنظیمات ← کنسول و آخرین کرش** (چکاپ سلامت، لاگ زنده‌ی هسته، آخرین استک‌تریس).
* روی CI: تست واحد + لینت + مانکی‌تست روی شبیه‌ساز.
* محلی: `gradle :app:testDebugUnitTest`

## حریم خصوصی

سروری در کار نیست، پس چیزی برای فرستادن هم نیست. بدون تله‌متری، بدون آنالیتیکس.
شماره و کد فقط به سمت سرورهای خود تلگرام می‌رود. تصاویر دوربین از رم بیرون نمی‌آیند.

مجوزهای شخص ثالث در [`NOTICE.md`](NOTICE.md).
